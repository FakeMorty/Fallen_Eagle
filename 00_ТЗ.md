# 1. Цель проекта

Создать сюжетный мод для игры **Age of History 2: Definitive Edition** (AoH2:DE, Steam app id **3381680**, разработчик Łukasz Jakowski), реализующий альтернативную историю Советского Союза и постсоветского пространства в период **1980–2080** (100 лет).

Отличительные особенности:
- **Нелинейное дерево решений**: каждое событие даёт ровно **3 варианта** (консерватор 🟥 / центрист 🟡 / реформатор 🟢).
- **Трёхуровневая модель последствий**: выбор → дуга «① НАЧАЛО → ② КУЛЬМИНАЦИЯ → ③ ФИНАЛ», у каждого шага — свои 3 терминальных решения.
- **Мультистрановый сценарий**: после путча 1991 игра разветвляется на 3 магистральные ветки и **15 республик**, у каждой — собственный сценарный путь.
- **Строгий реализм**: события основаны на реальных исторических развилках; фантастика допускается только как экстраполяция реальных трендов (климат, ИИ, демография) после 2020-х.

### 2.5.1. Python-структура (фрагмент из `gen_design.py`)

```python
def S(c, t): return (c, t)          # терминальный выбор: (цвет, текст)
def D(c, label, arc): return (c, label, arc)   # решение: (цвет, название, дуга)

# событие = {'year', 'title', 'trigger', 'decisions': [D, D, D]}
# arc = [(stage, subtitle, [S, S, S]) x3],  stage ∈ {'НАЧАЛО','КУЛЬМИНАЦИЯ','ФИНАЛ'}

{
 'year': '1982', 'title': 'Смерть Брежнева: кто преемник?', 'trigger': None,
 'decisions': [
  D('g', 'Андропов', [
    ('НАЧАЛО', 'Утверждение на посту', [S('r','через компромисс с элитами'), S('y','через Пленум'), S('g','немедленно')]),
    ('КУЛЬМИНАЦИЯ', 'Первые шаги', [S('r','кадровые перестановки'), S('y','экономический эксперимент'), S('g','антикоррупционная чистка')]),
    ('ФИНАЛ', 'Курс Андропова', [S('r','заморозить'), S('y','умеренный темп'), S('g','ускорить реформы')]),
  ]),
  D('y', 'Горбачёв (ранний)', [ ... ]),   # аналогично
  D('r', 'Черненко', [ ... ]),
 ]}
```

Коды цвета: `'r'` = 🔴 консерватор, `'y'` = 🟡 центрист, `'g'` = 🟢 реформатор.

### 2.5.2. Что должен сгенерировать генератор (реальный пример вывода)

Из события выше генератор `gen_events.py` уже производит такой файл (фрагмент):

```
id=ussr1982_смерть_брежнева_кто_преемник
title=1982 · Смерть Брежнева: кто преемник?
desc=Событие Смерть Брежнева: кто преемник? (1982). Выберите курс.
year_over=1981
year_below=1983
is_civ=ssr

option_btn name=Андропов

growth_rate=2
# реформаторский курс: риск, но рост
trigger_event=ussr1982_смерть_брежнева_кто_преемник_андропов_1
option_end
...
```

и для дуги (шаг ① решения «Андропов»):

```
id=ussr1982_смерть_брежнева_кто_преемник_андропов_1
title=НАЧАЛО · Утверждение на посту
desc=НАЧАЛО: Утверждение на посту (дуга решения «Андропов»).
has_variable=ussr1982_смерть_брежнева_кто_преемник
is_civ=ssr

option_btn name=через компромисс с элитами
stability=2
gold=-100
trigger_event=ussr1982_смерть_брежнева_кто_преемник_андропов_2
option_end
...
```

**Замечания разработчику:**
- Числа в исходах (`stability=`, `gold=`, `growth_rate=`) — **заглушки** (см. раздел 7.5), подлежат балансировке.
- `has_variable=<id ромба>` — метка «игрок выбрал именно это решение»; дуга срабатывает только после выбора родительского решения.
- `trigger_event=<id следующего шага>` — переход ①→②→③; на шаге ③ (ФИНАЛ) переходов нет (терминальные).

# 3. Доменная модель (как устроен контент)

## 3.1. Трёхуровневая структура решения

```
РОМБ (событие, год)
 ├─ ПРЯМОУГОЛЬНИК (решение №1) ──► дуга: ① НАЧАЛО → ② КУЛЬМИНАЦИЯ → ③ ФИНАЛ
 │                                    │            │               │
 │                                  (по 3        (по 3           (по 3
 │                                   решения)     решения)        решения)
 ├─ ПРЯМОУГОЛЬНИК (решение №2) ──► своя дуга
 └─ ПРЯМОУГОЛЬНИК (решение №3) ──► своя дуга
```

Правила:
1. **①→②→③ идут строго последовательно** (не одновременно).
2. У каждого шага дуги — **ровно 3 решения**.
3. Решения внутри дуги — **терминальные**: дают эффекты/флаги, но **не порождают новых событий**.
4. Долгосрочные эффекты (радиация, штрафы, инфляция) «тают» со временем — это **механика движка** (модификаторы с убыванием), в сценарии фиксируется только факт штрафа.

## 3.2. Цветовая семантика решений

| Цвет | Смысл | Типичные эффекты |
|---|---|---|
| 🔴 красный | консерватор / жёсткий | `+стабильность`, `−золото`, риск изоляции |
| 🟡 жёлтый | центрист / компромисс | умеренные эффекты, низкий риск |
| 🟢 зелёный | реформатор / либеральный | `−стабильность`, `+рост`, высокий риск/выгода |

## 3.3. Сквозные «оси» (накопительное состояние)

Игровое состояние, влияющее на финал, копится через исходы и читается триггерами:

- **Экономическая модель**: плановая / смешанная / рыночная.
- **Политсистема**: авторитарная / гибридная / демократия.
- **Темп реформ**: быстрый / умеренный / застой.
- **Национальная политика**: сила / союзный договор / игнор.
- **Гласность**: высокая / средняя / низкая.

> В движке оси маппятся на: форма правления (`government`), тип экономики (в AoH2:DE «религии» переделаны в «типы экономики»), `stability`, `growth_rate`, переменные (`has_variable`).

## 3.4. Хронология (6 эпох)

| Эпоха | Годы | Тема | Ключевые события |
|---|---|---|---|
| 1 | 1980–1991 | Кризис и перестройка | Афган, смерть Брежнева/Андропова/Черненко, Чернобыль, гласность, политреформа, парад суверенитетов, экономкризис, **путч** |
| 2 | 1991–2000 | После путча (3 ветки) | ГКЧП / Распад / ССГ; у республик — независимость, первые годы |
| 3 | 2000–2020 | Новый век | Консолидация, выборы, цветные революции, кризис-2008, конфликты |
| 4 | 2020–2040 | Технологический рубеж | Пандемия, энергопереход, ИИ/автоматизация, демография |
| 5 | 2040–2060 | Климат и ИИ | Климатический кризис, постдефицит, демографический коллапс |
| 6 | 2060–2080 | Финал | Стабилизация климата, космос, **гранд-концовки** |

## 3.5. Ветки после путча 1991

- **Ветка А «ГКЧП»** — СССР сохранён, жёсткий/мягкий курс.
- **Ветка Б «Распад»** — 15 республик (игрок выбирает страну), у каждой свой путь.
- **Ветка В «Конфедерация / ССГ»** — обновлённый Союз (конфедерация).

## 3.6. Список республик (Ветка Б)

Россия + 14: Украина, Беларусь, Казахстан, Эстония, Латвия, Литва, Грузия, Армения, Азербайджан, Молдова, Узбекистан, Туркменистан, Кыргызстан, Таджикистан.

## 3.7. Гранд-концовки (2080)

8 концовок (полные формулировки — в `epoch6_data.py`, `GRAND_ENDINGS`):
1. «Обновлённый Союз» 2. «Крепость» 3. «Многовекторный балансир» 4. «Распад на республики» 5. «Технологический прорыв» 6. «Климатический лидер» 7. «Сырьевой тупик» 8. «Авторитарная стабильность».

Концовка определяется итоговыми значениями осей (раздел 3.3) — точную матрицу «оси → концовка» разработчик должен специфицировать и реализовать как итоговое событие-финал.

Правило модов AoH2:DE — **повторять структуру корня игры внутри папки мода**, заменяя только изменённые файлы. Приоритет загрузки: мод → подписанные Workshop-моды → базовая игра.

## 4.2. Формат событий

AoH2:DE хранит события в **JSON (по файлу на событие)** ИЛИ в **старом текстовом формате** (который DE по-прежнему читает). Официальный синтаксис описан в файлах внутри игры:
- `game/_FAQ/Events.txt` — формат события
- `game/_FAQ/Events_Triggers.txt` — триггеры
- `game/_FAQ/Events_Outcomes.txt` — исходы

**Требование:** разработчик ОБЯЗАН сверить имена триггеров/исходов с этими файлами из конкретной установленной версии игры, прежде чем финализировать генератор. До этого использовать задокументированный текстовый формат (см. `формат_событий_AoH2DE.md`) как черновик.

### Текстовый формат события (эталон)

```
id=ussr1980_afghan
title=Афганистан: война затягивается
desc=Война идёт с 1979 года. Что делать?
year_over=1979
year_below=1981
is_civ=ssr

option_btn name=Эскалация
gold=-200
manpower=-5000
trigger_event=ussr1980_afghan_esc_1
option_end

option_btn name=Ограниченный контингент
gold=-50
trigger_event=ussr1980_afghan_ogr_1
option_end

option_btn name=Вывод войск

trigger_event=ussr1980_afghan_vyv_1
option_end
```

### Маппинг модели на механики (обязательный)

| Дизайн | Механика |
|---|---|
| Ромб (событие) | `id`/`title`/`desc` + триггер по дате (`year_over`/`year_below`/`exact_day`) |
| Решение | `option_btn name=` + набор исходов |
| Дуга ①→②→③ | цепочка событий через `trigger_event` (или по датам) |
| Терминальное решение | `option_btn` только с исходами |
| Метка/флаг | `has_variable=<id>` (id события запоминается при запуске) |
| Оси | `government=`, тип экономики, `stability=`, `growth_rate=`, переменные |
| Смена лидера | исход «сменить лидера» (см. Events_Outcomes) |
| Путч → 3 ветки | три разных `trigger_event` на события А/Б/В |

## 5.2. Входные данные

Структуры из раздела 2.2. Формат элемента уже устоялся:

```python
# S(color, text)                — терминальный выбор
```

## 5.3. Правила именования id событий

`<префиксстраны><год>_<slug-заголовка>` (латиница, без пробелов/диакритики), дуги: `_<slug-решения>_1|2|3`. Префиксы: `ussr` (Эпоха 1 и ветка А), `ssg` (ветка В), `rus` (Россия), по-республикам — короткие латинские коды (задать таблицу, см. 7.1).

## 5.5. Требования к качеству кода

- Python 3, без сторонних зависимостей, кроме стандартной библиотеки.
- Детерминированность (одинаковый вывод при повторном запуске).
- Генератор не должен «затирать» данные — только производить игровые файлы в отдельной папке `build/`.
- Логирование: сколько событий/решений/файлов сгенерировано.
- Юнит-проверки: каждый id уникален; каждое событие имеет ровно 3 решения; каждая дуга — 3 шага; ссылки `trigger_event`/`has_variable` ведут на существующие id.
