# Маппинг дизайна → события AoH2:DE

Как наша трёхуровневая модель переносится в реальные игровые события.

## Источник истины по синтаксису

В папке игры лежат официальные справочники (путь от корня игры):
- `game/_FAQ/Events.txt` — общий формат события
- `game/_FAQ/Events_Triggers.txt` — все триггеры
- `game/_FAQ/Events_Outcomes.txt` — все исходы
- `game/_FAQ/A_Mods_steam_workshop_READ_ME.txt` — структура мода

> **Важно:** точные имена триггеров/исходов для твоей версии игры сверяй по этим файлам. Ниже — рабочий формат из официального FAQ (общий для AoH2/AoH3, DE читает его как «старую систему событий»).

## Формат события (текстовый)

```
id=ussr1980_afghan                      # уникальный id
title=Афганистан: война затягивается     # заголовок (можно ключ локализации: title=afghan.t)
desc=Война идёт с 1979 года без результата. Что делать?
year_over=1980                          # триггер: год > 1980
year_below=1981                         # триггер: год < 1981
is_civ=ssr                              # получатель: цивилизация с тегом SSR

option_btn name=Эскалация               # решение №1
gold=-200                               # исход: −200 золота
manpower=-5000                          # исход: −5000 маны
trigger_event=ussr1980_afghan_esc_1     # исход: запустить следующее событие
option_end

option_btn name=Ограниченный контингент
gold=-50
trigger_event=ussr1980_afghan_ogr_1
option_end

option_btn name=Вывод войск
stability=5
trigger_event=ussr1980_afghan_vyv_1
option_end
```

## Маппинг нашей модели

| Элемент дизайна | Игровая механика |
|---|---|
| **Ромб (событие)** | событие: `id`, `title`, `desc`, триггер по дате (`year_over/year_below` или `exact_day`) |
| **Прямоугольник (решение)** | `option_btn` с `name=` и наборами исходов |
| **Дуга ①→②→③** | цепочка событий, вызываемых `trigger_event` (или по датам) |
| **Терминальные решения** | `option_btn` только с исходами (без `trigger_event`) |
| **Флаг (метка)** | `has_variable=<id события>` — при запуске события его `id` сохраняется как переменная цивилизации |
| **Ось `эк=плановая`** | реальные системы: форма правления (`government=`), тип экономики (в DE «религии» переделаны в типы экономики), `stability=`, `growth_rate=` |
| **Смена лидера** | исход «сменить лидера» (см. Events_Outcomes) |
| **Путч 1991 → ветки** | три разных `trigger_event` на три магистральных события (А/Б/В) |

## Правила цепочки

1. Решение ромба ставит «метку» = сам факт выбора кнопки (id события запоминается).
2. Дальнейшие события проверяют метку через триггер `has_variable=<id>`.
3. Сквозные оси (экономика, политсистема…) — это не флаги, а **состояния**: меняются исходами (`government=`, тип экономики, `stability=`), а читаются триггерами (`civ_government_is=`, `civ_religion_is=` и т.п.).

## Пример: наш «Курс Андропова» как цепочка

- `ussr1982_brezhnev` (ромб) → 3 кнопки → каждая `trigger_event` на своё событие-курс.
- `ussr1983_andropov` (дуга ①) → 3 терминальные кнопки (исходы) → `trigger_event` на ②.
- `ussr1983_andropov_k` (дуга ②) → … → `trigger_event` на ③.
- `ussr1984_andropov_death` — срабатывает только если `has_variable=ussr1983_andropov_*`.
